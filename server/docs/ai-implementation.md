# AI 辅助接入实现说明（0.4.0）

本版实现 [优化策略](ai-assistance-strategy.md) 第 15 节的首期范围：资料导入、协议草稿、样例验证、型号模板、从设备绑定及六个页面的模板复用。模型接口采用通用兼容方式，客户稍后配置服务。服务器版本为 0.4.0，API 版本为 1.10.0，数据库迁移版本为 3。

## 页面与操作流程

现有控制台增加三个页面，合计 **7 类、26 个业务页面和 1 个登录页、20 个菜单入口**。已实现目录见 [frontend-pages.json](frontend-pages.json)，历史策略目录保留为设计记录。

| 页面 | 已实现的功能 |
| --- | --- |
| P24 型号模板库 `/ui/device-models` | 查看已发布版本、协议和验证级别；查看应用计划并把模板带入现场表单 |
| P25 导入审阅工作台 `/ui/import-jobs/:jobId` | 资料证据、可视化字段与连接参数、问题处理、样例、保存、验证、发布；刷新后读取服务器草稿 |
| P26 模型服务设置 `/ui/system/ai` | 通用兼容接口及 Ollama、云端或内网模式、密钥、输出格式、图片能力、超时、额度、连接测试 |
| P05 蓝牙对端 | 从资料开始，或复用型号模板；选择实际地址和范围，登记后创建协议绑定 |
| P06 GATT 连接与操作 | 带入 UUID、读写或订阅参数；现场选择网关和当前连接，明确提交现有任务 |
| P07 自动连接规则 | 使用模板创建规则；真实对端和授权网关由用户选择，初始为关闭 |
| P10 解析器与试算 | 导入生成受限解析方案；已发布版本可直接用于 HEX 试算 |
| P11 解析规则包 | 按实际对端、绑定、包型、服务与特征 UUID 限定匹配；验证后明确激活 |
| P14 目标版本与字段映射 | 导入客户接口、验证顶层字段映射、带入新目标版本；核对地址、凭据和应用确认 |

推荐流程：在对应业务页面选择“导入资料” → 选择资源范围、文件和模型服务 → 审阅原文与草稿 → 核对独立有效/异常样例 → 保存并验证 → 管理员发布 → 从型号库选择现场对象 → 在对应页面提交实际操作。进入应用计划或发布模板本身不下发设备任务。

未配置服务时可以上传资料并创建人工草稿，也可以使用已发布模板。模型生成的样例统一标记为“模型建议”；用户核对后才能作为独立样例。模型返回的“已人工确认”或“问题已解决”不会被自动采纳。已有验证绑定草稿 revision 和内容摘要；修改后必须重新验证。发布版本不可原地修改。

## 模型接口与提取能力

在“系统管理 → 模型服务设置”中配置 Base URL、模型名称和 API 密钥。`OPENAI_COMPATIBLE` 调用 `/chat/completions`，Base URL 通常包含提供商的版本路径；`OLLAMA` 使用 `/api/chat`。JSON Object / JSON Schema、图片能力和 `max_tokens` / `max_completion_tokens` 由服务配置决定，是否兼容仍需用客户选择的实际模型验证。连接测试仅发送最小请求，不发送业务资料，但实际服务可能对此收费。

| 文件或参数 | 本版行为与限制 |
| --- | --- |
| TXT / Markdown | UTF-8 文本，保留来源位置 |
| DOCX | 提取文档文字；限制解压条目和总解压量，不执行宏与外链 |
| 文字 PDF | 优先调用管理员配置的 `pdftotext`；Windows 可配置 Python + pypdf 回退 |
| 扫描 PDF / PNG / JPEG | 需要支持图片的模型；PDF 还需 `pdftoppm`。图片结果需人工核对来源 |
| 导入大小 | 每任务最多 5 份，总计 50 MiB；PDF 最多 200 页；提取文字最多 2 MiB |
| 单次模型上下文 | 文字最多 160,000 字节；图片最多 20 页、每页 4 MiB、合计 12 MiB。超限明确报错，不静默截断 |
| 资料持久存储 | 默认累计 256 MiB，可由 `GW_AI_DOCUMENT_MAX_BYTES` 调整；单进程同时处理一个上传，保留数据管线的磁盘余量 |
| 作业队列 | 每用户最多 1 个未完成生成作业，实例最多 32 个排队或生成作业 |
| 用量控制 | 每提供商每日请求上限；记录尝试和返回的 token 用量，不承诺提供商费用估算 |

同一导入只生成一份型号/接口草稿。包含多个型号、多个固件协议或冲突表格时，用户必须选定目标并拆分资料或修订草稿；尚未实现候选型号自动拆分、页段裁剪和跨文档检索。合成教学资料见 [ai-demo-protocol.txt](examples/ai-demo-protocol.txt)，不能用作真实硬件兼容性证明。

同一资源范围再次上传相同哈希的文件时复用原文和证据 ID，不重复占用资料额度；每次导入仍建立独立草稿与审核记录。

管理员配置的模型密钥经现有密钥服务加密保存，API 不返回明文。云端发送需启用外发；内网模式仅允许回环/私有地址，显式开启后才能使用本地 HTTP。出站地址解析后固定目标地址、禁止重定向，并拒绝链路本地、元数据和组播地址。上传资料不能改变模型 URL 或调用设备工具。没有调用真实模型进行本次开发测试。

## 模块、存储与接口

```mermaid
flowchart LR
  F[资料与现场页面] --> D[上传及来源证据]
  D --> J[持久 AI 作业]
  J --> M[可选模型适配器]
  M --> R[人工审阅草稿]
  D --> R
  R --> V[确定性验证]
  V --> P[不可变模板与解析器]
  P --> B[对端绑定与规则包]
  G[网关原始报文] --> C[持久接管与采集证据]
  C --> E[固定版本解析器]
  B --> E
  E --> Q[映射及持久投递]
  Q --> A[客户应用确认]
```

AI worker 在 `manager` / `all` 角色运行，使用独立循环和短数据库事务。实时接管、解析、outbox 投递和客户 ACK 不调用模型。AI 作业有租约、取消、显式重试和调用预留记录；发生结果不确定的重启时不会自动重复付费调用。当前仍是同主机 SQLite 架构，未证明 AI 开启时的生产吞吐或 p95 延迟指标。

| 存储 | 结构和用途 |
| --- | --- |
| `management.db` | `ai_providers` 服务配置；`ai_documents` 文件元数据与证据；`ai_jobs` 作业状态；`ai_drafts` 可编辑草稿和验证；`ai_model_versions` 发布版本；`ai_apply_plans` 参数准备计划；`ai_usage` 调用预留与用量 |
| `management.db` 协议扩展 | `protocol_parsers` 不可变 DSL 版本和 compiler digest；`protocol_bindings` 真实对端身份与版本绑定；`gatt_discovery_snapshots` 已验证连接的 UUID/句柄映射 |
| `pipeline.db` | `processing_jobs.protocol_context_json` 冻结每次处理 revision 使用的协议证据 |
| 数据目录 `ai-documents/` | 以服务器生成 ID 保存源文件，鉴权下载，不作为公开静态文件提供 |

接口的完整字段、错误码、ETag、幂等键及权限以 [OpenAPI](../internal/platform/assets/openapi.json) 为准。新增接口族为 `/ai/status`、`/ai/providers`、`/source-documents`、`/ai/import-jobs`、`/protocol-drafts`、`/device-models`、`/ai/apply-plans`、`/protocol-bindings` 和 `/gatt-discovery-snapshots`，均位于 `/api/v1` 下。模型发布与解析器注册在同一管理库事务内完成。

ADMIN 管理服务与发布；DEVELOPER 在授权范围导入、编辑和验证；DEVICE_ADMIN 可读取模板并使用原有设备操作权限；AUDITOR 的模板只读权限不包含原文和样例；OPERATOR 保持原权限。模型和绑定按资源范围过滤，实际设备、目标和规则操作再次执行既有权限检查。

## 解析与连接约束

DSL 1.0 支持 RAW、BLE_AD 和 GATT_VALUE 单包数据，最多 128 个字段，包含 8/16/32 位有符号和无符号整数、字节段、大小端、无符号位域、比例/偏移、上下界、枚举、单位、固定字节和 CRC16-CCITT-FALSE 检查。拒绝未知字段、越界访问及任意程序代码；不执行 JavaScript、Python、Shell 或模型生成的脚本。

草稿同时包含解析与客户映射时，样例验证按“解析 → 对每条结果映射”的完整顺序执行，预期值应填写映射后的最终字段。映射缺字段或最终结果不符会阻止发布。

规则包冻结解析器 spec、compiler version、对端及绑定身份。GATT 规则必须限定真实对端或协议绑定，并限定服务/特征 UUID；仅凭网关型号或相同 UUID 不能推断从设备协议。事件保留原始 capture 格式，通过已验证任务建立连接映射；不能用“当前连接”覆盖历史报文的句柄含义。缺失或冲突的证据不会被猜测补齐；后到的发现证据只有在用户明确重解析并确认预览后才用于新的 revision。

本版沿用既有静态身份、定向发现、读取、受限写入、订阅及预置绑定加密能力。动态地址解析、配对、IRK 管理、完整服务树、厂商分包、私有加密和复杂嵌套映射仍需协议和固件扩展。验证级别仅为 `DOCUMENT_REVIEWED` 或 `SAMPLE_VERIFIED`，没有自动授予实机验证级别。

## 部署和升级

Windows 在构建前端后运行 `scripts/build.ps1`，本地部署使用 `scripts/deploy-local.ps1`。PDF 工具可通过 `-AIPythonPath`、`-AIPdfTextPath`、`-AIPdfRasterPath` 传入绝对路径；脚本将路径保存在该实例忽略提交的 `ai-tools.json` 中，重启继续生效。Python 回退需要对应解释器已安装 pypdf。容器构建已加入 Poppler 工具；客户环境应通过设置页确认提取能力。

升级前停止同数据目录的所有管理/数据进程，再以原版本 `gatewayctl backup --data-dir ... --out ... --key-file ...` 制作加密备份。归档和独立备份密钥必须放在数据目录之外。备份覆盖模板、原文、绑定和密钥等整个数据目录。

本版按顺序校验并执行数据库 v3 迁移；旧数据和 v1/v2 迁移校验和保持不变。同库迁移失败整笔回滚。升级成功后若必须回退，应恢复升级前完整备份并使用原程序，并按 [运维说明](operations.md) 完成恢复后的 revision 对账；只替换旧二进制不能读取 v3 数据库。多进程部署必须同时升级，不能混跑不识别新解析器的旧 worker。

本次实施和实测结果见 [0.4.0 验证记录](ai-validation.md)。策略中的其他页面自然语言诊断、全文问答、批量部署、自动增量差异和真实资料质量基准集属于后续增强，不以入口数量代表已交付。
