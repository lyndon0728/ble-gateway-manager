# 服务器 0.2.0 实现与验收范围

本版在 V1.7 分层实现基础上适配 GW32I33V2 嵌入式协议 1.1，API 契约版本 1.8.0。目标是客户服务器上的单机可运行版本；管理与数据可分进程运行，使用本机 SQLite WAL 数据库。原有参考协议 1.0 保留；新型号按已提供的 ESP—服务器与 UART 设计稿实现服务端和模拟器，真实固件尚需联调。

| 模块 | 本版实现 |
| --- | --- |
| 身份与权限 | 首次本地初始化、人/应用账号、固定角色及实例/项目/组范围、应用令牌、浏览器会话、CSRF、撤销、审计 |
| 网关管理 | 签名设备清单、参考网关本地登记、身份绑定、分组、在线状态、能力列表 |
| 上行接入 | HTTPS 与 MQTT 入口；批量原始数据、稳定身份、内容冲突、T1 原文/收据/处理任务同事务后确认 |
| 解析与路由 | 透传、解码、隔离；BG 18 字节参考帧、4 字节演示帧、BLE AD 结构；不可变规则包验证与本机激活 |

逻辑分层通过模块和事务边界实现；B 部署的两个进程共享同一主机本地数据目录，并非跨主机微服务或 HA。接口契约共 65 个操作，启动页和契约下载另外提供。客户端字段 `CONFIGURE.parameters.expectedReportedRevision` 与服务端给设备的 `desiredRevision` 分开定义。

## 必须保留的运行约束

- MQTT 遥测、任务结果、状态使用独立有界队列；四个客户投递 worker 对目标进行租约隔离。有限 worker 不等于无限多慢目标隔离，客户应设置合理超时及容量。
- T2 为一个事件的所有目标原子生成输出。任一目标达到队列额度会反压该事件的所有目标；网络重试在目标额度内独立进行。
- 数据文件与 WAL 都计入额度，另保留至少 128 MiB 磁盘余量。新数据超过额度会收到可重试拒收；已存在且内容相同的事件仍返回重复确认。128 MiB 是软件预留策略，不能阻止系统其他进程占用磁盘。
- 交付完成且超过原文期限后可清理载荷；身份、处理和确认锚点当前保留。长期运行会增加元数据和数据库文件，额度耗尽需要扩容或经过验证的离线归档。本版没有自动历史锚点归档，也不会为腾空间静默删除未完成数据。磁盘空间监控必须覆盖 SQLite 主文件、WAL 和制品。
- 新厂商协议需新增可信解析器代码及测试后发布；不执行上传的任意脚本。现有解析器每事件输出一条记录，多记录数量变化及组替换须在扩展协议后验收。
- 参考网关仅声明配置、重启、诊断。GATT/OTA 服务端任务与验签路径不证明实际无线操作、Flash 写入或固件回滚已完成。
- Broker 身份和 Topic ACL 必须另外配置并验收；HTTP 网关凭据入库不等于 Broker 自动开户。
- 生产 TLS、容器实际运行、目标服务器容量、真实网关断电与无线丢包尚需现场测试。本机测试不构成万级设备或生产可用性承诺。

后续硬件开发直接使用 `gateway-protocol.md` 与 `reference-sensor.md`；客户接口使用 `openapi.json` 和 `customer-mapping.md`。真实验收应先确定一个网关 SKU、每秒事件量、报文大小、离线积压时长和客户接收能力，再运行相应负载与断电测试。

## 0.2.0 数据与升级

保持 migration 1 的 SQL 内容及已保存校验和，新增管理库 migration 2 的对端、自动规则、触发记录、连接、订阅、对端占用六张表，以及数据库 capture 消费记录。升级启动自动迁移，任一步失败整体回滚；不重建旧数据库。新摘要统一按 LF 计算；兼容旧 Windows CRLF 与 Linux LF 两种等价摘要，除此之外的内容变化继续拒绝，已有校验记录不重写。

1. 停止旧版 manager/pipeline，使用旧版维护工具生成加密备份，保存配套二进制和密钥。
2. 两个进程同时升级至 0.2.0，保持数据目录、namespace、节点身份及密钥不变。先完成启动与就绪检查，再开放设备接入。
3. 回退必须停机、用原版工具将升级前备份恢复到空目录，再启动匹配的旧二进制。禁止把 0.1.0 直接连到已经迁移的生产数据库，也禁止新旧 manager/pipeline 混跑。

1.0 历史解析器摘要保持不变；新 BLE AD 解析必须显式选择 `ble_ad@1.1.0 / ble-ad-2`。1.1 capture 与原事件同事务持久化，重试保留原版本。控制消费确认前不回收 capture 原文；管理进程长期停机会使积压持续增长，达到额度后向设备返回背压。

自动连接任务的 `autoTrigger` 由服务器生成，公开手工任务接口禁止注入。规则创建/修改需要 `gatt:manage`，执行需要作用域内 `gatt:execute` 与 `task:create`；每次触发在管理事务中重新校验当前授权。已创建的任务按既有任务取消和结果语义处理，停用规则仅阻止后续触发。配置 `cooldownMs` 是两次尝试的最小间隔，连接结束后另至少冷却 30 秒；UNKNOWN 持续占用，等待真实设备证据对账。

基础管理页增加蓝牙对端、自动连接规则和 GATT 连接查询。规则创建与修改使用已发布 API，操作示例见 `protocol-v11-integration.md`；本版没有提供完整的可视化规则编辑器。
