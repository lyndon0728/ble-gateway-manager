# ESP32-S3 验证计划与验收用例

版本：1.1；基线日期：2026-11-19。依据为 [ESP 需求](esp32s3-requirements.md) 的 **170 条需求、44 个 ESP-AT 用例**。实现次序见 [开发文档](esp32s3-development.md)，持久事务与恢复设计见 [持久化文档](esp32s3-persistence.md)。线上字段仍以 [服务器协议](../server/docs/gateway-protocol.md)、[消息 Schema](../server/internal/platform/assets/message-contracts.schema.json)、[UART 协议](../server/docs/gateway-uart-protocol.md) 为准。

**本文是待执行计划，不是测试报告。全部 ESP 用例状态为未执行；当前没有可运行的 ESP 固件测试入口。** 仓库中已有服务器测试、nRF 主机替身测试和 Python 串口参考工具，可核对对端契约，但不能证明 ESP 的存储、驱动、并发、网络、射频或升级已经完成。本文不新增脚本或代码。新增本地配网、凭据部署及配置对账的待实现契约见 [网络配置设计](esp32s3-network-provisioning.md)；不能将其当作现有服务器 Schema 已支持的字段或入口。

## 1. 测试分层与运行条件

| 层次 | 验证对象 | 必需条件 | 不能替代的证据 |
| --- | --- | --- | --- |
| H：ESP 主机测试 | 编解码、状态机、定时器、事务恢复、合并算法、任务防重 | 待实现的 ESP 可测试模块、确定性时钟及接口替身 | 实际 Flash、任务抢占、DMA、CTS、TLS、BLE 控制器行为 |
| K：SDK 目标构建/测试 | 锁定 ESP-IDF/依赖的 ABI、配置、链接、分区与驱动适配 | 真正 ESP 工程、锁定 toolchain/依赖、目标配置 | 仅编译不能证明执行时序或实板可用 |
| B：实板测试 | 双芯片、电源、Flash、网络接口、BLE 空口、硬件复位 | 匹配 PCB、已验证可运行镜像、独立可控供电/复位、抓包/测量设备 | 替身状态或打印日志不能证明物理动作和掉电恢复 |
| S：服务器集成测试 | 实际 API/Schema、身份、任务、持久 ACK、能力与结果校验 | 隔离测试实例、测试凭据/公钥、可恢复数据库及必要 Broker | 服务器接受结果不能独立证明设备实际执行 |

一条用例可分层执行，但只有其要求的层次均有有效证据才完成验收。未具备板卡、签名构建、时间引导或对应业务模块时，标记阻塞原因，不能以“模拟通过”替换“实板通过”。本文件没有触发真实服务写入、烧录、复位、断电或 eFuse 操作。

## 2. 接口替身、故障注入和判定原则

| 接口/边界 | H 层计划提供的控制能力 | B/S 层必须补充的验证 |
| --- | --- | --- |
| UART 字节流 | 分片、粘连、重复、CRC/长度错误、延迟、旧会话帧、明确 BUSY | 实际 RTS/CTS、TX 排空、中止、驱动溢出和逻辑分析仪帧边界 |
| 持久存储 | 在预留、写记录、写索引、提交、发布、GC 的每个边界停止；短写、损坏、满盘、慢写 | 真正断电及恢复后的存储内容；函数返回成功不足以证明持久 |
| 时钟/调度 | 单调时间和 UTC 独立推进、跳变、锚失效、回调乱序 | 重启、真实调度延迟、校时及长期漂移测量 |
| 云端传输 | 可控 HTTP/MQTT 响应、逐项 ACK、身份/批号错配、网络切换 | 真实 TLS/ACL/Schema/数据库提交；抓包确认探测走指定接口 |
| BLE | 原始 ADV/SCAN_RSP、连接/断连、MTU/CCC、重复回调、超时 | 两路独立控制器、可编程对端、空中抓包和对端实际写入计数 |
| OTA/启动 | 候选槽、运行槽、会话和启动身份、校验/确认失败 | 正式机制的签名验证、试启动、槽交换、回滚与实际电源故障 |
| 本地配网/浏览器 | 配网窗口、认证会话、重复请求、localRevision 冲突、AP/STA 切换和离线提交 | 手机/笔记本真实浏览器、SoftAP 连接、接口隔离、凭据保护及平台对账 |

替身和注入点均为待实现测试设施，不能开放成未经认证的生产网络/手机命令。生产构建须关闭注入入口，并有构建检查证据。所有随机测试保留种子；每个关键提交边界至少覆盖故障发生前、发生中、完成后，循环次数和覆盖率在实施时冻结，不能只挑一次成功重启。

掉电必须区分三种拓扑：**仅 ESP 断电且 nRF 保持运行、仅 nRF 复位、整板断电**。前两种须确认供电隔离真实有效；不能将整板断电后已消失的 nRF RAM 记录作为可重放前提。

判定以不可变身份和真实提交/动作次数为准：维护输入观测、nRF 批次、ESP 事务、平台事件、任务结果、对端副作用之间的核对账。事件可有被明确记录的未接管损失，不能有无证据的接管、静默删除、重复物理写入或凭空成功。

## 3. 通用前置与证据包

每次运行记录：用例/子场景、需求版本、ESP/nRF/服务器提交与镜像摘要、SDK/toolchain/依赖锁、PCB/接线/电源拓扑、制造配置及能力清单、输入、故障点、随机种子、重试次数、观察结果和执行人。凭据仅记录引用或脱敏指纹，私钥/token/Wi-Fi 密码不得进入证据包。

证据应包含适用的：原始 UART 帧和 ACK、GPIO/电源波形、脱敏 MQTT/HTTP 记录、空中抓包、持久日志恢复前后快照、服务器事件/任务查询、测试对端动作计数、内存/Flash/延迟曲线。比较日志须明确哪个时间来自单调钟、哪个来自可信 UTC，避免用未同步时间推断因果。

运行状态使用“未执行 / 阻塞 / 通过 / 失败”；通过必须关联原始证据和运行范围，缺少某层证据就保留该层未完成。文档结构检查、编译成功、服务器 ACK、UART OK 分别记录，不能互相升级为业务验收通过。

## 4. ESP-AT-01～44 详细用例

### ESP-AT-01：UART 黄金向量与损坏输入

- **分层/现有可运行**：H、K、B；ESP 入口未实现，未执行；可参考 R-UART。
- **前置**：冻结 UART 帧黄金向量、最大合法长度、控制和数据类型；ESP 流式解码器接入可记录副作用的替身。
- **注入**：在每个字节边界切分，连接多帧，插入空分隔、错 CRC/magic/version/长度、超长输入、未知类型和旧 link_id。
- **步骤**：逐一输入合法/非法向量；在坏帧后紧接有效 HELLO/控制帧；目标构建后通过真实 UART 重放。
- **预期**：合法帧与 nRF 向量一致；非法帧不执行动作、不分配无界内存；到后续边界恢复解析，业务串口没有日志污染。
- **证据**：输入/输出字节、解码判定、动作调用次数、内存检查及实板串口抓取。

### ESP-AT-02：CTS、溢出与 TX 中止

- **分层/现有可运行**：H、K、B；ESP 入口未实现，未执行；R-UART 仅提供帧级参考。
- **前置**：实际 UART 引脚/电平/缓冲所有权已冻结；可独立拉动 CTS，具有逻辑分析仪和驱动事件记录。
- **注入**：长 CTS 阻塞、RX overflow、driver buffer full、传输中取消/复位；同时排入 ACK 和控制请求。
- **步骤**：最大帧双向持续发送；分别停顿和中止；在旧 TX 取消/排空后恢复；验证完整 TX 完成前没有启动响应超时。
- **预期**：无缓冲提前复用、帧交叉或第二控制请求覆盖；恢复后可握手；GPIO8正常释放，普通溢出不造成无记录的 nRF reset。
- **证据**：UART/CTS/RTS/复位波形、驱动事件、帧摘要、缓冲生命周期和恢复时间。

### ESP-AT-03：控制请求重试、冲突与 BUSY

- **分层/现有可运行**：H、B；ESP 入口未实现，未执行；参考 R-UART、R-BLE。
- **前置**：单在途控制调度器及请求持久映射；替身能记录请求 ID、opcode、内容及受理次数。
- **注入**：动作受理后丢响应；同 ID 改内容；旧会话响应；明确 BUSY；在待决请求期间触发诊断轮询。
- **步骤**：依次重试、重握手、查询动作；BUSY 后以新 msg_id 重发未受理请求，GATT 保留原 op_seq；分别逼近计数上限。
- **预期**：丢响应重发同 ID/字节；明确 BUSY 才进入新 ID 路径；跨重握手按 op/session 对账；旧响应不完成新请求，副作用最多受理一次。
- **证据**：完整请求/响应顺序、缓存和 journal 状态、op_seq/tx_seq 映射、替身/对端动作次数。

### ESP-AT-04：提交前仅 ESP 断电

- **分层/现有可运行**：H、K、B；ESP 持久测试入口未实现，未执行；无可替代的现成 ESP 测试。
- **前置**：nRF 独立保持供电；首批及后续批次分别测试；存储事务具有可识别的完整提交边界。
- **注入**：观测写入中、水位写入中、提交标记完成前切断 ESP 电源。
- **步骤**：发送批次，确认尚未完整提交即断电；保持 nRF 原启动 ID 和队首；恢复 ESP 并重放。
- **预期**：断电前未发送 CUSTODY；恢复忽略不完整事务，nRF 保留的批次重新完整接管；只生成一份有效观测/事件。
- **证据**：独立电源波形、nRF boot ID、CUSTODY 时刻、存储残片与恢复后的批次/观测账。

### ESP-AT-05：提交后、CUSTODY 前仅 ESP 断电

- **分层/现有可运行**：H、K、B；ESP 入口未实现，未执行；R-UART 可参考批次重放语义。
- **前置**：nRF 独立供电；观测与批次水位已作为一个事务持久提交；阻止 ACK 发出。
- **注入**：提交完成后、ACK 出线前关闭 ESP。
- **步骤**：恢复 ESP；核对原 nRF boot ID；重放相同批次与 payload，随后再发送下一批。
- **预期**：最近批次同 type/摘要只回 CUSTODY，不再插入观测；下一批连续接管；已交付云端事件的回收不清除最近 UART 水位。
- **证据**：事务提交证明、重放字节、水位恢复、观测/事件计数与重复 ACK。

### ESP-AT-06：CUSTODY 后、云端 ACK 前断电

- **分层/现有可运行**：H、B、S；ESP 入口未实现，未执行；参考 R-SERVER 的接入去重。
- **前置**：含待合并观测、已定稿事件及两种 schemaVersion 的持久数据；云端暂不返回接管 ACK。
- **注入**：CUSTODY 后断电；服务器已提交但响应丢失；分别测试仅 ESP 与整板掉电。
- **步骤**：恢复后对失去旧时间映射的待定观测单独定稿，原定稿事件按原身份重发；恢复云端 ACK。
- **预期**：已接管记录可恢复；旧 eventId/sequence/版本/载荷不变；服务器仅 ACCEPTED/DUPLICATE；新 espBootId 不重写旧事件。
- **证据**：接管水位、待定区到事件事务、上行重复摘要、服务器原始事件数及回收记录。

### ESP-AT-07：RAW_PERSISTED 后 GC 中断

- **分层/现有可运行**：H、K、B、S；ESP 入口未实现，未执行；R-SERVER 仅验证云端重复接纳。
- **前置**：同一存储段混有已接管、未接管、隔离事件及控制/结果记录；GC 保留完整副本和索引发布边界。
- **注入**：复制新段、提交索引、标记旧段可回收和擦除各阶段掉电/短写。
- **步骤**：收到合法逐项云端 ACK 后触发回收；逐点恢复，校验全部记录；对恢复为待确认的旧事件再次上传。
- **预期**：未交付记录不丢；已提交记录不产生第二个事件身份或物理动作；允许同一 eventId 安全重传并得到 DUPLICATE；UART 水位独立保留。
- **证据**：GC 前后存储图、提交顺序、记录集合比对、云端去重结果及控制预留空间。

### ESP-AT-08：水位损坏、跳号和摘要冲突

- **分层/现有可运行**：H、B；ESP 入口未实现，未执行；参考 R-UART。
- **前置**：已接管非首批且 nRF 继续运行；具有可诊断的损坏隔离和维护流程。
- **注入**：删除/损坏持久水位；批号前跳；最近同批号改 payload/type；有效 CRC 下构造非法记录；另注入早于最近水位的旧帧。
- **步骤**：恢复并提交上述批次；重新 HELLO 后观察；在批准的维护场景中记录后执行受控 nRF reset。
- **预期**：不能把中途批次当新起点；冲突/非法批次 FAULT，旧于最近水位的帧忽略；HELLO 不清除 nRF FIFO FAULT；复位前明确未接管 RAM 数据风险。
- **证据**：损坏样本、FAULT/诊断记录、ACK和HELLO序列、维护决定及连续性缺口记录。

### ESP-AT-09：配对时间边界与多候选

- **分层/现有可运行**：H、B；ESP 合并算法入口未实现，未执行；没有现成 ESP 去重测试。
- **前置**：两路相同完整观测、可控单调时钟/误差、稳定入队次序；冻结事件分配与观测消费事务。
- **注入**：时间差加误差在50 ms边界内/等于/之外；多个候选时间差相同；到期前后新候选到达；定稿事务中断。
- **步骤**：推进各观测等待至150 ms；检查最小时间差及先入队规则；恢复中断的配对提交。
- **预期**：仅合法异源记录一对一合并，以 nRF 为主；每条最多配对一次；配对提交后恰有一个事件且两条观测被消费，未提交则可恢复重做定稿。
- **证据**：输入时间表、误差计算、候选选择轨迹、事务恢复和一对一核对账。

### ESP-AT-10：不得合并的观测

- **分层/现有可运行**：H、B、S；ESP 入口未实现，未执行；R-SERVER 可核对 capture 语义。
- **前置**：固定相近时间；组合地址类型、原始 AD、报告种类、connectable、legacy/SID等元数据。
- **注入**：同源重复、同地址不同AD、ADV/SCAN_RSP混合、匿名/bond未知地址、扩展报告缺SID、不可比属性和迟到记录。
- **步骤**：输入正反例；同一个 UUID/MAC 多次周期发送；真实双扫描与空中记录对照。
- **预期**：不合并反例、不永久抑制同源周期广播；unknown不补造地址；只有真实合法配对才写精确 observedBy 数组。
- **证据**：输入/输出集合、空口与两路抓取、独立定稿计数、服务器 capture 校验结果。

### ESP-AT-11：重启、锚过期与 UTC 跳变

- **分层/现有可运行**：H、B、S；ESP 入口未实现，未执行；R-UART/R-SERVER 仅作时间字段参考。
- **前置**：已建立有效 nRF→ESP 单调锚和 UTC 锚；含待定观测与已定稿事件。
- **注入**：任一芯片重启、锚龄跨60秒、TIME_PROBE重试/超50 ms往返、UTC前后跳、长时间积压的旧capture_ms。
- **步骤**：刷新探测，尝试用新锚处理旧积压；重启后恢复待定区；重传已定稿事件。

- **证据**：脱敏候选/实际配置、各字段边界、接口路由/认证证明、localRevision/transactionId、状态阶段和失败原因，以及服务器实际接入证据。

### ESP-AT-40：首次离线配网与 LOCAL_ONLY 保存

- **分层/现有可运行**：H、K、B、S；离线保存及上线对账待实现，未执行。
- **前置**：分别准备首次无 last-good 设备和已有可恢复 last-good 设备；平台/互联网不可达但本地网页可用；可查询持久配置及状态。
- **注入**：无 UTC、DNS/TLS/设备认证不可用、用户不确认离线保存、明确确认后浏览器断开、保存期间掉电及之后恢复平台连接；后台验证尚未结束时提交较新配置，令旧挑战响应晚到。
- **步骤**：输入语法合法配置；先验证普通应用不能被错误标成功，再通过明确的 LOCAL_ONLY 选择保存。重启检查实际生效/回退策略与管理入口，恢复网络后走真实在线验证和配置对账；分别检查 desiredLocalNetwork、actualNetwork 与 activeInterface，并在旧验证完成前制造 networkGeneration/snapshotId 变化。
- **预期**：LOCAL_ONLY 只能由授权用户明确选择，页面说明尚未验证平台连接；不能由超时自动升级为成功。保存 activeLocalSnapshot、本地版本、来源、未验证原因及回退依据，保留 lastVerified 快照及凭据；首次无历史配置走受控重配路径。没有云任务、可信 UTC或平台确认时不伪造 TaskResult/desiredRevision/observedAt；后续上线也不能自动把本地版本当作平台已提交版本，必须完成规定的对账。保存目标和当前实际网络不能合成一个状态误报；后台验证发布前必须重新取得网络租约，并以 snapshotId/networkGeneration 作 CAS 核对。旧证据丢弃或重验，不覆盖较新配置，也不再次推进配置修订。
- **证据**：用户确认记录、持久 localRevision/transactionId、LOCAL_ONLY 状态、掉电恢复状态及旧配置保留证明、后续验证/对账的实际请求和服务器记录、目标/实际网络与当前接口、租约及 CAS 冲突证据。

### ESP-AT-41：本地候选回退与提交边界断电

- **分层/现有可运行**：H、K、B；共享网络候选管理器和本地 journal 待实现，未执行。
- **前置**：last-good 与候选完整快照、对应凭据引用、可控提交边界、独立 ESP 供电；准备未交付事件、活跃任务及网络事务。
- **注入**：凭据提交前后、候选日志提交前后、验证中、配置提交前后分别断电；故意输错密码/IP；浏览器因信道迁移断连；重复应用/状态查询，试用超时或用户取消。
- **步骤**：每点恢复后读取事务和实际驱动配置；核对 old/candidate/localRevision；通过同一 transactionId 重连查询，不重新提交；验证失败路径能重新进入授权管理窗口并恢复上联。
- **预期**：未提交候选恢复原生效快照，已有 last-good 不丢；已提交恢复对应 activeLocalSnapshot，LOCAL_ONLY 保持未验证标记且 lastVerified 仍可用于明确回退。重启不会重置试用预算使不确定候选无限试用；浏览器断连本身不视作成功或立刻回滚，以事务期限/阶段为准。配置、凭据引用、localRevision 和事务终态原子一致；重复请求不重复提交，身份/spool/云任务证据保留。
- **证据**：电源/提交边界、存储恢复快照、驱动读回和实际路由、事务查询/重试次数、回退原因、旧凭据与业务数据集合。

### ESP-AT-42：平台远程网络配置与凭据缺失

- **分层/现有可运行**：H、K、B、S；R-SERVER 提供既有网络配置校验参考，ESP 执行器和远程凭据投递扩展未实现，未执行。
- **前置**：合法管理员、在线已认证设备、可用且属于目标设备的 credentialRef；有效 CONFIGURE/network 任务；与 AT-17/18 相同的真实候选接口证明条件。
- **注入**：不存在/已撤销/不属本机的引用、错误密码、未实现的凭据投递请求、未授权用户、过期任务、首次 probe 与 SUCCEEDED 同批、断网和 ACK 丢失；本地来源 credentialRef 没有 deliveryId、状态重复上报、伪造安装来源和引用其他设备本地凭据。
- **步骤**：平台修改 SSID、引用、IPv4 和 uplinkOrder；先验证凭据存在再试用；逐接口提交稳定 resultId 的 networkProbe，取得前一服务器事务的 RESULT_PERSISTED 后才提交配置和成功结果。新增密码部署只在完整扩展实现后按其独立契约测试。另测试本地 PUT_CREDENTIAL 安装后，在设备网络状态中上报 LOCAL/INSTALLED 的 ref/version 及 SSID/security 绑定，服务器以认证设备归属登记引用，再执行 ADOPT_LOCAL。
- **预期**：现有 CONFIGURE 不接受明文 Wi-Fi 密码或擅加字段；凭据不存在时明确失败并保留旧网络，不尝试无密码/降级连接。平台修改密码需求不能被“credentialRef 字符串已保存”冒充完成。扩展未实现时界面禁用并明确原因，仍列为待交付；已实现时必须证明凭据安全部署、设备归属及安装确认后再引用。本地安装声明不要求不存在的云 deliveryId，不伪造投递回执，不上传密码；登记只授予该设备引用，并不替代密码正确性和网络可用验证。任务成功同时满足实际网络验证、逐项持久 ACK 和配置提交。
- **证据**：权限/字段拒绝结果、脱敏凭据部署与安装确认（适用时）、服务器任务/修订号、逐接口抓包、probe/result ACK 提交顺序及设备回读、本地安装元数据登记/归属及重复上报结果。

### ESP-AT-43：双入口竞争、版本对账与 OTA 互斥

- **分层/现有可运行**：H、K、B、S；统一事务仲裁、本地对账及相关平台扩展待实现，未执行。
- **前置**：同一 gateway 同时有授权本地会话和平台管理用户；独立 localRevision、desiredRevision、实际快照摘要；可使设备处于网络候选、ESP/nRF OTA 和试启动确认阶段。
- **注入**：两端同时应用、旧 baseLocalRevision、本地保存后迟到远程任务、云端新修订与本地未对账修改、相同请求 ID 不同载荷、OTA 与配网互抢资源、重启后旧窗口/旧确认请求；ESP 本地快照与服务器旧网络基线不同、裁决时仍有未下发/已发送/UNKNOWN 旧任务。
- **步骤**：按各竞争顺序提交并观察唯一网络 owner；拒绝后重新读取状态再提交。恢复云端后分别测试管理员接受本地配置、明确下发平台配置以及继续保持冲突待处理；执行时重核对版本/摘要，不能仅在请求入队时检查。对 ADOPT_LOCAL/APPLY_PLATFORM 验证候选 uplinkOrder 的全部接口，覆盖两端基线差异。分别依法取消尚未下发的冲突任务、等待已发送任务的设备终态/对账证据，以及保留无安全终结证据的 UNKNOWN。
- **预期**：每时刻至多一个网络候选；冲突显式 BUSY/版本冲突且不静默覆盖。localRevision 不占用 desiredRevision；平台未纳管本地变更时不假报同步。对账选择不能绕过正常候选验证、任务授权或旧数据保留；裁决任务不得只按某一端旧基线的差异缩减探测接口。旧任务占用须按证据合法释放，UNKNOWN 不删除/改成功，也不能只暂停下发就绕过单活动任务限制创建裁决；无法安全终结时明确阻塞。没有相应云契约时保留“待对账”，不在普通状态/结果消息塞入未知字段。OTA/试运行义务与网络切换互斥；页面可读但不得中断确认预算或抢占升级。
- **证据**：两端请求/到达顺序、owner/journal、版本与摘要、各拒绝原因、对账前后实际网络、完整 uplinkOrder 的各接口探测证据、旧任务取消/终态与占用释放账、UNKNOWN 保留状态、任务结果以及 OTA 确认时间线。

- **步骤**：各客户端连接热点、认证、扫描/手填、编辑、应用、重连查询并关闭；记录 AP/STA 实际信道/子网和 BLE/UART/spool 压力。重复浏览器刷新/返回，等待窗口收尾后继续正常上报。

## 7. 失败处理与报告更新

发现接管后数据丢失、重复物理写入、绕过授权/验签、错误镜像确认、无证据成功或不可恢复存储破坏时，相关阶段不得放行。保留最小复现输入、故障种子与原始证据；修复后重跑受影响用例和关联恢复路径，不只重跑正常流程。

后续报告分开列出本次新增通过、仍未执行、明确阻塞和失败项。变更SDK、驱动、PCB、分区/持久格式、镜像密钥或协议字段时，按覆盖索引选择重新验证范围并记录原因。任何测试结果必须绑定具体构建；不得沿用另一板卡/另一镜像的通过标签。
