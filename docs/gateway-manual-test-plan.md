# GW32 网关人工测试执行总册

文档版本：1.0；日期：2026-11-19。适用对象：网关管理平台、ESP32-S3 0.3.0、nRF54L15 0.3.0。**本册是交给人工执行的测试计划，不是测试通过报告。所有新增人工用例初始状态均为“未执行”。**

## 1. 本次交接范围

测试人员按“服务器 → ESP32-S3 → nRF54L15”的控制方向操作，按相反方向核对扫描、连接和升级结果。保留两份协议：板内UART协议、网关到平台协议；独立手机蓝牙业务不列为本次必测。

| 纳入本次人工必测 | 测试内容 |
| --- | --- |
| 扫描与过滤 | nRF/ESP独立扫描、名称/UUID/RSSI/major/minor掩码、REPORT/PAIR、旧规则兼容、完整配置读回 |
| 上传 | ESP跨射频去重、原始字节与身份保留、断网缓存、重投、逐项持久ACK |

**“手机蓝牙业务”范围说明：** 代码中已经存在C05独立蓝牙业务扩展，但用户未明确要求该业务。ACC-11、ESP-AT-25及C05专用客户端/route/业务ACK场景列为“范围待确认”，不计入本次必测通过率，不要求测试人员开发手机App。本册不删除这些历史编号，也不表示已经从源码移除扩展。手机通过Wi-Fi网页配网和本地OTA仍为必测。

可连接广播、连接暂停/恢复属于现有BLE链路能力，可用标准BLE测试客户端验证；这不要求启用C05的独立业务协议。ESP-AT-21保留广播热更新/故障回滚必测部分，连接子场景按本批已授权的可连接广播能力执行并分别记录，不能因排除C05而略过广播错误恢复。

### 4.1 已知门控与容量约束

- 自定义nRF板默认`GW_RADIO_VERIFIED=n`；未完成本板时钟/FEM/RF核验时，不得把无扫描结果判为过滤失败，也不能为跑用例直接勾选射频已验证。
- ESP默认`GW_SETUP_BUTTON_GPIO=-1`、`GW_FACTORY_AUTHORIZED_SETUP=n`，没有默认热点入口。`sdkconfig.local-setup-test`仅为首次未配网提供一次600秒窗口，不能用于假设每次重启都可再次配网；正式按键/替代现场入口由固件工程师先核实。
- ESP受控nRF复位默认关闭。只有本板接线/有效电平/脉宽/释放等待核实后，相关测试才可启用；普通UART错误不应自动触发复位。
- 两radio配置独立；当前连接数量与角色并发受实现/板级能力限制。不要把“同时扫描并广播、多连接、首次蓝牙配对”当作已开放能力；冲突拒绝是应验证的行为。
- `gwstore`完整快照有96KiB预算，任务身份最多保留64项；清理大结果不等于释放防重身份。目前没有供测试人员任意清空账本的归档API。制定每轮任务预算，达到容量应背压/拒绝新工作并保留旧证据。多轮可换已准备的测试样机；不得为继续测试直接删除journal、伪造ACK或格式化存储。长期运行是否满足业务频率，必须单独记录该容量限制。
- 普通0.2.x设备升级0.3.0前须准备新时间/设备信任材料；网络凭据配置接口不能改制造信任根。缺材料导致的TLS拒绝应先归为前置阻塞，不能通过关闭验签绕过。

## 5. 上板准备人工用例

以下用例初始状态均为**未执行**，不因前版CI通过而自动变更。

### MAN-PREP-01：三方构建与实际安装版本

**关联：** ACC-17、ESP-AT-34。**人员：** 固件/平台工程师提供材料，测试负责人复核。

**步骤：**

1. 填写第3节的源码SHA、SDK、板版本、构建配置、依赖锁和镜像摘要；平台填写进程/容器及嵌入前端来源。
2. 取得本轮nRF实际目标构建日志、map和DFU签名链；区分DK、自定义板、DFU变体，不互相替代。缺任一被测变体即停止该变体后续测试。
3. 由安装负责人按已有制造/部署流程准备样机和隔离平台。测试人员记录安装结果，核实际ESP应用描述、nRF HELLO版本/boot、平台构建身份及数据库迁移5记录。
4. 核对当前固件能力与制造授权/板级验证交集；旧版本/能力不足的设备应明确拒绝V2等扩展。
5. 保存构建和安装证据，再进入对应正常业务用例。

**预期：** 每个被测组件来源可追溯；没有把主机测试、网页版本或ESP编译替代nRF目标构建；未授权能力不开放。**证据：** 版本登记表、构建/安装记录、脱敏HELLO/状态和迁移日志。**恢复：** 无配置变更；安装失败保持安装负责人的恢复流程。**阻塞：** 无对应目标产物、板版本不匹配、无法证明实际部署版本。

### MAN-PREP-02：身份、信任材料和离线入口

**关联：** ESP-AT-16、ESP-AT-34、ESP-AT-37、PLAT-GW-AT-01。

**步骤：**

1. 在测试材料清单中逐项核对身份、证书/公钥指纹、NVS/加密配置、setup材料和可重复开窗方式；不在报告中抄录秘密。
2. 由制造负责人确认测试设备可以读取制造区且不会因缺钥自动擦除。使用正式现场入口开启热点，按网络分册验证登录；不能以原首次测试窗口代替重复开窗能力。
3. 核对时间服务配置、实际服务端时间源和板级漂移依据。正常签名时间可用后再进行远程TLS/任务测试。
4. 使用专用缺材料样机或受控测试配置执行负例：缺时间公钥/授权时远程依赖可信时间的操作被拒绝；本地离线认证路径按网络/OTA分册单独验证。

**预期：** 不使用共享默认身份、明文业务控制或跳过证书验证恢复联网；缺材料有明确拒绝/阻塞证据。**证据：** 指纹/配置开关清单、登录和时间状态、拒绝原因。**恢复：** 由制造负责人恢复测试材料，不通过普通配网API改信任根。**阻塞：** 无合法制造输入、开窗或时间依据。

### MAN-PREP-03：UART、供电及故障拓扑

**关联：** ACC-03、ESP-AT-02、ESP-AT-04～06、ESP-AT-35。

**步骤：**

1. 由硬件人员对本板确认UART引脚/公共地/电平及交叉流控；仅确认后接入观察夹具。串口参数按当前协议为1,000,000 baud、8N1、RTS/CTS。
2. 正常上电抓取HELLO和一组控制/数据往返，确认业务UART无控制台日志。
3. 分别记录整板掉电、仅ESP掉电、仅nRF复位时两芯片供电波形及boot变化，确认观察夹具不会维持原应掉电芯片供电。
4. 记录每种故障的触发方法、测量通道、实际持续时间及可复现误差，交给分册中的断电用例使用。

**预期：** 三种拓扑能被区分；只在nRF保持原boot时才讨论其RAM批次重放。**证据：** 接线版本、波形、boot记录。**恢复：** 回到标准供电，重新握手并核目标。**阻塞：** 接线未经核对、无法独立掉电/复位或无测量证明；相关子项不得改用整板断电冒充。

### MAN-PREP-04：本板RF/FEM与能力放行

**关联：** ACC-18、ESP-AT-34、ESP-AT-44。**人员：** 硬件/射频工程师。

**步骤：**

1. 对本轮板版列出HFXO/FEM/天线与供电核验记录、仪器/夹具和批准的测量限值。不得直接采用历史资料中的典型值作为量产通过阈值。
2. 按该板受控调试流程测量时钟启动、FEM TX/RX互斥、建立/保持时间、供电电流及天线口输出；分别记录单radio和拟启用组合。
3. 根据测量记录批准本轮测试能力集合，再由固件/制造负责人形成对应配置。默认未验证配置继续保持关闭。
4. 在测试记录中注明该结论只适用于本板版和配置，不能推广至全部射频组合/距离/吞吐。

**预期：** 能力有对应实测证据；没有以芯片规格或源码存在替代测量。**证据：** 原始仪器记录及阈值/审批表。**恢复：** 恢复本轮批准配置；异常停止RF相关测试。**阻塞：** 无该板限值、工具、人员或测量记录。

### MAN-PREP-05：证据与恢复演练

**关联：** ESP-AT-34，全部故障用例的前置。

**步骤：**

1. 保存测试平台可恢复备份及设备初始完整配置、凭据引用、版本、队列与任务基线；备份存放受控位置，不提交GitHub。
2. 用一个独立隔离恢复目标验证平台备份可读，并由设备安装负责人验证测试样机救援路径；记录结果，不覆盖其他测试批次。
3. 对本轮会用到的精确断电点、ACK丢弃、控制器/Flash失败列出工装或专用调试镜像。无准确触发/观察条件的项目提前标阻塞。
4. 复制记录模板，建立目录和证据编号，完成一次普通配置的“输入—实际动作—设备结果—平台ACK”完整取证，再开始异常测试。

**预期：** 故障后能解释并恢复本轮测试环境；没有虚构生产注入API或用手动随机断电冒充指定提交边界。**证据：** 备份/恢复演练、夹具版本、首条完整事务记录。**恢复：** 返回批准的测试基线。**阻塞：** 无恢复材料、不可观察指定故障点或证据无法脱敏。

## 6. 执行和判定规则

1. 每条用例先填实际板/固件/平台版本、目标radio、场景数据与前置状态。相同用例在nRF/ESP、MQTT/HTTPS、不同浏览器上需分别记录适用轮次；不从一个目标推定另一个通过。
2. 每次配置查询并保存当前目标、有效值和revision，使用平台分配的新修订；不在设备上自造云端revision。单组配置按实际接口执行，不把两个radio或扫描/广播组拼为平台不支持的请求。
3. 记录taskId/resultId、batchId/eventId、设备boot、UART会话和连接引用。禁止只凭HTTP 2xx、MQTT PUBACK、UART OK或网页提示“已发送”判成功。
4. 正常流程至少按分册规定次数重复；无明确次数的功能场景先做3次独立运行，均保留证据。该默认次数仅为本轮人工回归安排，不是产品可靠性指标。精确边界/掉电测试每个子点分别记录，不以随机次数代替覆盖。
5. 对RSSI精确值、500/501ms及Flash提交点等难以空口/人工精确构造的场景，使用经确认的注入夹具并标为“受控注入”；另做真实RF/Flash对照。只有注入通过时，实板相关层仍保留未完成。
6. 发现与当前合同不符应登记缺陷；若原需求在本版本尚无实现/工具，列阻塞或未满足，不能修改预期结果使测试变绿。存储迁移、自动归档等未提供的入口不得补写成现有操作步骤。
7. 每个故障用例结束恢复网络/广播/扫描目标、释放已确认结束的连接和维护状态，并核队列对账。UNKNOWN或未决副作用先对账，禁止通过删任务、清存储或重复升级跳过。

| 状态 | 适用条件 | 是否计为通过 |
| --- | --- | --- |
| 未执行 | 尚未开始人工操作 | 否 |
| 阻塞 | 缺工具、目标镜像、制造输入、现场入口、需求阈值或可观察证据 | 否；填写原因/负责人 |
| 通过 | 该适用轮次全部预期满足且证据完整 | 是 |
| 失败 | 实际结果偏离预期、数据不完整、重复副作用或证据与结果矛盾 | 否；关联缺陷 |
| 范围待确认 | C05独立手机蓝牙业务等范围未确定 | 不纳入本次必测分母；保持公开列示 |
| 不适用 | 本批明确不包含某硬件变体/授权能力，并有负责人说明 | 不纳入本批分母；不代表需求删除或能力通过 |

## 7. 数据核账与长稳阈值

每轮至少关联：对端已发送记录 → 控制器收到/过滤输出/明确丢弃 → ESP已持久接管 → ESP定稿eventId → 平台RAW_PERSISTED → 客户交付（若本轮包含）。跨射频配对可能使两条观测形成一条事件，应按身份和observedBy核算，不能直接要求“发包数等于事件数”。

掉电前nRF尚未被ESP接管的RAM记录有明确损失边界；实物无法知道的损失数量填“无法确定范围”，不得捏造精确数。已经CUSTODY的数据必须由ESP恢复负责；客户收到/应答与平台原始持久接管分别记录。

| 72小时长稳输入/阈值 | 开始前冻结值 |
| --- | --- |
| 设备数、radio组合、对端/广播速率、载荷大小及规则集 | 待填写 |
| 在线/离线时间表、最大离线量与可用持久容量 | 待填写 |
| 每轮配置/控制任务数及64身份/96KiB预算 | 待填写 |
| 上报/控制延迟统计口径与允许上限 | 待填写 |
| 各接管边界允许损失/重复判定 | 待填写；不得放宽已接管数据完整性 |
| RAM最低余量、趋势判定、Flash写入/寿命预算 | 待填写 |
| 无记录重启、死锁、假ACK、重复物理副作用 | 不允许 |
| 时钟漂移与误差证据 | 待填写；使用本版100ppm授权须有依据 |

阈值未确定不能把72小时“仍能登录”当作长稳通过。容量不足导致的明确背压与实际业务频率是否可接受，分别填写技术结果和产品结论。

## 8. 缺陷、复测与交接完成条件

缺陷建议分级：P0为已接管数据丢失、越权、写错组件/运行槽、重复不可逆副作用等；P1为必需流程无法完成或错误成功/回退；P2为有明确绕行的界面/诊断问题。等级由测试负责人根据实际影响确认，不自动替代团队缺陷规则。

提交缺陷需包含最短复现步骤、版本、脱敏输入、期望/实际、稳定ID与证据、当前设备状态及恢复情况。修复后在新提交重跑失败子项和直接相关回归，保留原失败记录；不得覆盖成首次通过。

人工交接完成需满足：适用范围已签字；全部必测轮次有记录；P0/P1已关闭或明确未放行；阻塞/范围待确认/不适用项单独列出；要求的目标构建和实板证据齐备；镜像、平台、配置与测试结论一致。未达到这些条件时只出“阶段性测试报告”，不写整机或量产验收通过。
